## 优惠券（v1.4）：券后价进预算

用户问「预算实现有对优惠券的考虑吗」→ 答案是没有，选定补到 B 档（券进预算）。

### 探测结论（真实接口，scripts/probe-coupons.js → data/coupon-probe.json）
- `query-my-coupons`：账号有 **5 张真实券**，markdown 返回，字段为「券名 / 优惠:¥X(用券价格) / 有效期(含星期+每日时段) / 标签(到店|外送)」。
  **不返回 couponId/couponCode**。参数是 string 类型的 page/pageSize（上限 200，最多 5 页）。
- `query-store-coupons`：有结构化字段（couponId/couponCode/products[].productCode），但门店 1450713 返回 `data:[]`。
- `available-coupons`：只有券名+图片，无结构化字段，不能进求解。
- `query-promotions`：仅团餐（beType=6），到店场景不适用。
- `query-meal-detail`：参数是 **code 不是 productCode**；返回的 `rounds` 只是定制项（选蘸酱等），
  **拆不出套餐完整子项** → 套餐仍无法算热量，继续排除在可信池外（9900005456 在该店还直接"未匹配到商品"）。

### 生效规则（红线：宁可不用也不虚报）
唯一匹配 + 券后价严格低于促销价 + 时效/星期/时段/渠道全中 + 非组合券，才 applied；
否则 skipped 并给真实原因。当前 5 张券 **applied=0**（2 张券后价反而更贵、2 张商品不在本店菜单、组合券+未到生效日）——真实结果，不是 bug。

### 硬限制（必须写进前端文案）
券接口不给券码 → `calculate-price` 无法带券 → 券后价只影响组合选择与预算判定，**不承诺实付**。
`/api/order` 仍按促销价核价。前端展示券省必须带 disclaimer。
