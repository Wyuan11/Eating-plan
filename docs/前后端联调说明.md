# 前后端联调说明（针对 Wyuan11/Eating-plan 的 web/）

> 结论：**后端只要跑在 3000 端口，前端一行都不用改就能联通。**
> 但有一个一处必须确认的字段，和一个 v1.1 引入的备选渲染问题，见下文。

## 一、好消息：不需要 VITE_USE_MOCK

前端用的是**自动回退**，不是环境变量开关：

- `vite.config.js` 把 `/api` 代理到 `http://localhost:3000`
- `src/lib/api.js` 捕获请求异常 → 回退 `src/mock/*.json`
- 所以它后端不在线也能演示；**后端一在线，自动走真实链路**

## 二、必须做的一件事：后端跑在 3000 端口

前端代理目标是 3000，我的服务默认 8787。已经改好了：

```
start.bat  → PORT=3000
```

双击起来后访问：

```
http://127.0.0.1:3000/api/health
```

返回 `"count": 124` 即成功。前端 `npm run dev` 后刷新页面，
顶部那条「内置演示数据」蓝条消失，就是联上了。

如果你手动跑，记得加端口：

```bash
MENU_FILE=./data/menu-1450713.json PORT=3000 node server/api.js
```

## 四、我发现的一处字段不一致（已在本侧兼容）

`web/src/lib/api.js` 的 `getStores`：

```js
const list = Array.isArray(data) ? data : data.stores || [];
```

但 Schema v1 的 `StoresResponse` 约定字段是 **`items`**，后端返回的也是 `items`。
按原文会导致门店下拉永远为空。

**已处理**：本侧 `/api/stores` 同时返回 `items` 和 `stores` 两份，现在能正常工作。

**建议前端顺手改正**（一行，保持契约唯一来源）：

```diff
- const list = Array.isArray(data) ? data : data.stores || [];
+ const list = Array.isArray(data) ? data : data.items || [];
```

改完之后，我这边的兼容别名可以去掉。

## 五、v1.1 引入的一个渲染问题（需要前端改）

`web/src/components/ResultView.vue` 里，备选方案重算时把数量**强制设为 1**：

```js
const items = (alt.value.items || []).map((it) => ({ ...it, quantity: 1 }))
...
const altItems = computed(() => alt.value ? (alt.value.items || []).map((it, i) => ({ ...it, qty: 1, key: i })) : [])
```

这在 Schema v1 下是对的（当时备选把「同款两份」拆成了两条记录）。
但 v1.1 起备选 `items` **带 `quantity`**，例如「双层吉士汉堡 ×2」是一条 `quantity: 2`。
前端仍按 1 计算会得到：

```text
重算 ¥23  vs  声明 ¥46  →  判定不一致
```

**需要改成：**

```diff
- const items = (alt.value.items || []).map((it) => ({ ...it, quantity: 1 }))
+ const items = (alt.value.items || []).map((it) => ({ ...it, quantity: it.quantity || 1 }))
```

以及明细渲染处展示数量（否则用户看不到「×2」）：

```diff
- <li v-for="it in altItems" :key="it.key">
+ <li v-for="it in altItems" :key="it.key">
    <span class="alt-list__name">{{ it.name }}<template v-if="it.quantity > 1"> ×{{ it.quantity }}</template></span>
```

```diff
- const altItems = computed(() => alt.value ? (alt.value.items || []).map((it, i) => ({ ...it, qty: 1, key: i })) : [])
+ const altItems = computed(() => alt.value ? (alt.value.items || []).map((it, i) => ({ ...it, quantity: it.quantity || 1, key: i })) : [])
```

注：主方案那条链路（`lib/verify.js`）已经正确处理了 `it.quantity || 1`，**不用动**。

## 六、可选优化（不影响联调）

| 项 | 现状 | 建议 |
|---|---|---|
| 主方案 tab 文案 | `PlanTabs.vue` 硬编码「均衡推荐」 | 改成读 `result.objective` 映射，因为我们现在支持指定主方案目标 |
| 「本方案菜品 N 件」 | 用 `result.items.length` | 改成 `sum(quantity)`，两份同款应算 2 件 |

第三条做完，演示脚本里「同句话切换三个方案」才真正对等——否则备选只有简版明细。
