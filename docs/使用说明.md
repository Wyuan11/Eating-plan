# 麦门智选助手 · 使用说明

> 面向使用者与评委。想看技术架构与接口契约，请读 `README.md` 与 `docs/api-schema.md`。

## 一、一键启动

双击项目根目录的 **`start.bat`**，会同时启动：

- 后端 API：`http://localhost:3000`
- 前端页面：`http://localhost:5173`（浏览器自动打开）

前提：Node.js 18+；首次使用先在 `web/` 下执行 `npm install`。  
如果 3000 端口被旧进程占用，先关掉旧进程再启动，否则会连到旧代码。

命令行方式：

```bash
node server/api.js     # 后端 3000
cd web && npm run dev  # 前端 5173
```

## 二、怎么点单

### 方式一：一句话（推荐演示用）

在「一句话点单」输入框直接说人话，例如：

```
两个人，热量1200cal，不设预算，不吃辣，想吃个麦香鸡
```

系统会自动识别：

| 你说的                   | 系统理解的约束                |
| --------------------- | ---------------------- |
| 两个人 / 三个女生            | 人数                     |
| 预算60 / 80块钱           | 预算上限                   |
| 热量1200cal / 控制在1500大卡 | 热量上限（按单位区分，不会和预算搞混）    |
| 不设预算 / 不限预算 / 随便花     | 不约束总价，只按热量/忌口求解        |
| 不吃辣 / 不要饮料 / 不吃牛肉     | 忌口（原料级、品类级均可）          |
| 想吃两个麦香鸡 / 来个辣堡        | 正向诉求（数量是硬约束；辣堡=麦辣鸡腿汉堡） |
| 划算 / 便宜点              | 优化目标切换为「最省钱」           |

说完点「生成方案」即可。输入框下方会实时显示「已识别：……」，确认无误再提交。

### 方式二：表单精确控制

下方表单可手动设置：门店（支持浏览器定位或按城市搜索）、预算（可关闭=不设上限）、人数（1~5）、热量上限（可关闭）、忌口多选、想吃什么（chips 可删）。

### 方式三：命令行（Skill / 调试用）

```bash
node server/emit-plan.js --traceId demo-001 --budget 60 --calorie 1200 --people 2 --exclude 辣 --want "麦香鸡x2"
```

支持的参数：`--budget`（`none` 表示不设）、`--calorie`、`--people`、`--exclude`、`--want`、`--note`、`--objective`（balanced / cheapest / lowest_calorie / max_value）、`--store`。方案落盘到 `data/skill-outbox/plan-<traceId>.json`。

## 三、看懂结果页

- **3 套方案**：均衡推荐 / 最省钱 / 预算吃满，标签页切换，每套都满足全部硬约束，只是优化目标不同。
- **手动微调**：每件商品可增减数量，也可从「全部菜单」加菜；每改一步实时重算，超预算或超热量会被当场拦截。
- **进度条**：预算/热量占用一目了然；未设上限时显示「—」。
- **披露横幅**：无法满足的诉求（比如该门店没有这道菜、或被忌口过滤）会如实告诉你原因，而不是默默忽略。
- **下单**：确认方案后点下单——系统先按本地快照算期望价，再走麦当劳 MCP 实时核价；**价格变了会拦截并让你确认**；确认后生成支付链接，到链接为止，不会自动支付。

## 四、常用自检命令

```bash
node scripts/demo-check.js                        # 演示前自检（8 项）
node scripts/demo-check.js --online               # 额外实测 MCP 连通性（需 Token）
node test/test-solver.js ./data/menu-1450713.json # 求解器回归
node test/test-api.js  ./data/menu-1450713.json   # 接口回归
node test/test-order.js ./data/menu-1450713.json  # 下单链路回归（默认不创建真实订单）
node scripts/build_mock.js                        # 重生成前端演示 Mock
```

全部 exit=0 才算健康。

## 五、Token 配置（可选）

不配 Token 也能完整体验点单（菜单读本地快照、下单用演示订单）；要体验**实时核价与真实下单链路**才需要：

```bash
cp .env.example .env   # 填入 MCD_MCP_TOKEN（从 ~/.workbuddy/mcp.json 里 Bearer 后那串复制）
```

后端启动时会自动读取 `.env`，无需手动 set 环境变量。

## 六、边界与红线

- 下单止于**支付链接**：会调用 `create-order` 获取订单号与链接，但**不支付、不自动跳转**。
- 菜单里没有官方营养数据的单品，热量恒为 `null`，不估算、不当 0。
- 菜单快照没有冷热标注时，系统会如实说明「未替你过滤」，不伪造冷热判断。
- MCP 限流 600 次/分钟；演示固定门店 `1450713` + 到店自取。
