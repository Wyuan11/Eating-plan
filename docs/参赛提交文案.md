# 1024 切磋大会 · 参赛提交文案

## 作品名称

麦门智选助手

## 一句话介绍

输入一句自然语言（预算、热量、忌口、人数），系统基于麦当劳官方 MCP 数据做确定性组合求解，输出不超预算、不超热量、避开忌口的可下单点餐方案。

## 作品说明

**使用方式**

双击 `start.bat` 一键启动（后端 3000 + 前端 5173）。最省事的用法是只说一句话：「两个人，热量1200cal，不设预算，不吃辣，想吃个麦香鸡」——系统自动抽出预算、热量、人数、忌口和正向诉求，直接给出方案；也可以用表单精确控制。结果页一次给出 3 套方案（均衡推荐 / 最省钱 / 预算吃满）互相切换，还能手动增减菜品或从全菜单加菜，每改一步都会实时重算并独立校验，超预算超热量会被当场拦下。支持浏览器定位选门店，6 家门店菜单缓存可切换。

**亮点**

1. **AI 只抽约束，不编答案。** 大模型只负责把自然语言变成结构化约束（五槽位语义模型：硬约束 / 排除 / 诉求 / 目标 / 披露），配了 12 条带反例的回归用例防幻觉：分清「两个人」和「两个麦香鸡」、识别「划算」是目标不是菜名、辣堡能对上麦辣鸡腿汉堡、「不要饮料」过滤整个饮品品类。诉求数量是硬约束——想吃两个麦香鸡，方案里就恰好两个。
2. **答案是算出来的，可复算。** 求解器是确定性枚举：只用官方营养数据的可信池，金额全程用「分」做整数运算，无解时告诉你最低价和最低热量的下界、该放宽哪一项。前端还会拿返回数据独立重算一遍，金额热量对不上就不展示——两套独立实现互相校验，这是"AI 结果可信"的底气。
3. **不编造，就披露。** 菜单里没有营养数据的单品热量恒为 null，绝不猜；菜单没有冷热标注时，如实告诉你"未替你过滤，也未伪造冷热判断"，而不是假装做到了。
4. **下单严格止于支付链接。** 下单前先按本地快照算期望价，再走 MCP 实时核价，价格变了直接 409 拦下让你确认；确认后只生成支付链接，不支付、不自动跳转。既演示了完整的交易链路设计，又守住了"不真实下单"的安全边界。

**实现思路**

Skill 位于链路核心（约束提取的规则、陷阱清单、回归用例都沉淀在 Skill 包里），Web 只是渲染层。后端是零第三方依赖的原生 Node.js，五分钟就能在本机跑起来；方案落盘采用 tmp→fsync→rename 原子写，接口与落盘共用同一份结构（前端一套解析吃两个来源）；接口契约用三态 `status`（success / nosolution / error）表达，前端不靠 HTTP 状态码猜业务结果。

### 备选：精简版（表单有字数限制时用）

输入一句话自然语言（预算/热量/忌口/人数，还支持"想吃两个麦香鸡"这类正向诉求），系统基于麦当劳官方 MCP 菜单数据做确定性组合求解，一次给出 3 套可下单方案。AI 只抽约束不编答案（12 条反例用例防幻觉），求解器只用官方营养数据、金额按分做整数运算，前端还会独立重算一遍互相校验；缺数据就如实披露而非编造；下单止于支付链接，先核价、变价自动拦截。后端零依赖原生 Node，start.bat 一键启动。
